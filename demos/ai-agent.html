A run, start to finish

A run is one task. Every run goes through the same stages, and each stage shows up in the window as it happens.

StepWhat Relay doesWhat you seeTypical time
PlanReads your sentence, picks the tools it needs and lists the steps.The task and the tools it will open, before anything runs.1 to 2 s
ReadPulls only the records in scope: the tickets, threads or rows the task names.A count of what was read from each tool.2 to 10 s
WorkGroups, matches, drafts or fills in fields, one step at a time.Each step with its state and how long it took.5 to 40 s
CheckCompares the output with the task and reruns a step that failed, up to twice.Any retry, with the reason.1 to 5 s
ApprovalStops before sending, deleting or paying and waits for a person.A bar with Approve, Edit and Skip.up to 24 h
ResultWrites the summary and posts or saves it where you asked.The summary, with a link to every record it touched.1 to 3 s

Approvals

Relay reads and prepares as much as you allow. Some actions always stop and wait for a person, on every plan, and that cannot be switched off.

Sending
Email, public ticket replies, direct messages and the first post in a channel.
Deleting
Records, pages, messages and rows. Where a tool has an archive, Relay archives instead.
Paying
Refunds, charges, invoices and anything else that moves money.

On Team you choose who can approve for each agent. A request nobody answers within 24 hours is skipped and written to the audit log.

API

Start a run with one request and receive a webhook each time its state changes. The API is part of the Team plan.

# Start a run
curl -X POST https://api.relay.example/v1/runs \
  -H "Authorization: Bearer $RELAY_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "task": "Summarize the tickets opened this week",
       "tools": ["zendesk", "slack"] }'

# Response
{ "id": "run_4827", "state": "running" }

Security

Read-only by default
A new connection can read and nothing else. You turn on write actions per tool and can turn them off again at any time.
Scoped keys
Each API key lists the tools and actions it may use. A key made for Zendesk cannot open Gmail.
Audit log
Every run, step, approval and key change is recorded with the person and the time. Team workspaces can export it as CSV.
Data kept 30 days
Run inputs and outputs are deleted after 30 days. You can delete a single run sooner from its page.
SSO on Team
SAML sign-in through Okta, Google Workspace or Microsoft Entra ID, with the option to require it for everyone.
Where data is hosted
On AWS in Oregon (us-west-2). Data is encrypted in transit and at rest, and is not used to train models.

What counts as a run?

One task from start to finish, however many steps or tools it uses. A run that stops for approval and is then skipped still counts as one.

Can Relay send something without asking?

Not email, public replies or payments. Sending, deleting and paying wait for a click on every plan. Smaller write actions, such as tagging a ticket, run on their own once you turn them on for a tool.

What happens when a step fails?

Relay retries the step twice. If it still fails, the run stops there, shows the error and leaves everything after it untouched. You can rerun from the failed step.

Is our data used to train models?

No. Inputs and outputs are used to complete the run and are deleted after 30 days.

How do we change plan or cancel?

From Settings, then Billing. An upgrade starts right away. A cancelled plan runs to the end of the period you paid for, then the workspace moves to Free.
